# Первый архитектурный аудит BANKFLOW

Исходная точка — main, `e2fac087fbd9215b1781040bfab3e93baba44d1d`. Среда эксперимента — Linux, Python 3.12.14, Node v24.22.3.

## Архитектура и приоритеты

1. Pages раздаёт готовые файлы из корня репозитория. Сборщик объединяет данные семи модулей, общие CSV/SQL, документы и реестр заданий, собирает ZIP и пишет каталог, HTML и список ресурсов. Хеш содержимого определяет версию офлайн-кэша. Физкультура представлена отдельно от семи программных комплектов. До эксперимента PR мог попасть в main без проверки этой цепочки.
2. Маска `docs/*.md` автоматически добавляла любой новый отчёт в пользовательский каталог и офлайн-кэш. Перед правкой критерием регрессии выбрано побайтовое совпадение существующих артефактов при добавлении инженерного отчёта. Одно изменение в сборщике задаёт явный список трёх прежних документов в прежнем порядке. Это управляет составом каталога. При публикации из корня Pages остальные файлы репозитория по-прежнему могут быть доступны по прямому URL.
3. В двух комплектах отсутствовал README. Добавлены указатели на существующие материалы. Сравнение ZIP с main показало, что каждый получил только свой README, а содержимое всех прежних записей совпало. В списке PWA появились ровно эти два пути. Каталог и версия кэша обновились. HTML, стили, прикладной JS, маршруты и ключи браузерного хранилища имеют нулевой diff.
4. Локальный Python API использует SQLite и запускается отдельно. Быстрый CI проверяет статическую поставку. Интеграционные проверки записи в БД и переноса прогресса выполняются отдельным браузерным сценарием с временной базой.

## Границы проверки

Лёгкая задача GitHub Actions выполняет сборку, JS, SW и проверку целостности при PR и push в main. Для браузерных тестов нужны Playwright и системный Chromium. Проверка через HTTP прошла; проверка прямого открытия файла остаётся открытой для среды, разрешающей file URL. SW-тест моделирует события кэша. Установка PWA на реальном устройстве в эксперимент не входила. Новые документы для учебного каталога нужно явно добавлять в перечень сборщика. Правила работы и команды приведены в корневом AGENTS.md.
