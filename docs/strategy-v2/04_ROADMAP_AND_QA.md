## Этап 0 — Freeze and audit
Создать tag/ветку `v1.2-stable`; проверить `main`, размеры, архивы, текущий Pages. Загрузить подлинные задания; написать `requirements.json` из доказательств. Вести `AUDIT.md`, `OPEN_QUESTIONS.md`, `DECISIONS.md`. Не создавать файлы с придуманием условий.

## Этап 1 — Academic compliance
1. ПИС: перестроить таблицы, оформить единый курсовой Word-документ (рамки/штампы, 3 аналога + реальные скриншоты) по методичке.
2. ИИС: воспроизвести в Google Colab, собрать снимки из Colab и зарегистрировать согласование датасета.
3. ИСиТ: запуск MySQL, верификация 19 запросов, корректная КР по личному варианту, печатный отчёт.
4. СИТ: буквальное сопоставление каждого из 45 пунктов оригиналу; запустить Express; пометить №7–10 как неизвестные.
5. Стандартизация: назначить вариант; заполнить три модели надёжности с реальными исходными параметрами методички.
6. БД, ВМИП, физра: не блокировать остальные предметы, но получить оригиналы.

## Этап 2 — Product architecture
Разнести index-бандл на модульный исходный код без ломания автономной копии. Добавить source-of-truth registry, проверяемые API contracts, состояние загрузки, error handling, типизированные объекты/схемы, Unit и End-to-End. Режимы offline/SQLite/MySQL показать честно.

## Этап 3 — Premium UI/UX
Новая навигация «Обзор → Предмет → ЛР → Проверка → Сдача», режим преподавателя, компактные списки на планшете, графическое качество схем и аналитики, доступность, качество микроинтеракций; подпись стилусом только на частном устройстве.

## Критерии завершения работы (Definition of Done)
1. Требование подтверждено источником либо явно обозначено как гипотеза.
2. Реализация и фактический запуск есть; отсутствующий инструмент не изображать запущенным.
3. Для каждого пункта есть свидетельство (тестовый вывод, лог, реальный скриншот).
4. Отчёт отражает фактически сделанное, числа воспроизводимы, графики подписаны.
5. Никаких реальных банковских данных, секретов, закрытых документов в public.
6. Автотесты, проверки сборки и визуальный тест планшета прошли.
7. Отдельный ZIP проверен распаковкой и запуском.
8. Сохранена предыдущая стабильная версия; новый код доступен в GitHub и Pages (или честно обозначен как не опубликованный).
9. Для «Сдано» имеется фактическое событие передачи; для «Принято» — подтверждение преподавателя.

## Измерители успеха
- Доля подтверждённых требований = источник A/B / всего проверяемых **найденных** требований, не 8×8.
- Покрытие тестами заданий = решённые+проверенные / точно назначенные.
- Пройдённые смоук-тесты перед защитой = все контрольные сценарии (целевой 100%).
- Нет публичных секретов/конфиденциальных материалов (обязательное условие).
- Пакеты преподавателей распаковываются и содержат README/код/результаты/отчёт.

## Риски
**Самый большой академический риск:** демонстрационный банковский пример подменяет обязательный индивидуальный вариант. **Самый большой продуктовый риск:** удобный публичный index содержит встроенные бинарные комплекты и потенциально будущие персональные данные. **Самый большой технический риск:** offline/PWA и SQLite имеют разные копии состояния без миграции. Исправления этих трёх рисков первоочередные.
